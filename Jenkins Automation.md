# 🚀 Automate Jenkins with GitHub Webhooks

Until now, the CI/CD pipeline was started manually by clicking **Build Now** in Jenkins.

In this final step, we will remove that manual action.

After configuring a **GitHub Webhook**, every time code is pushed to the `devops-php-todo` repository, GitHub will notify Jenkins and Jenkins will automatically:

1. Checkout the latest code.
2. Build the Docker image.
3. Push the image to Docker Hub.
4. Deploy the new image to Kubernetes.
5. Wait for the Kubernetes rollout to complete.

The final workflow becomes:

```text
Developer
    │
    │ git push
    ▼
GitHub Repository
Tamiru-Assefa/devops-php-todo
    │
    │ HTTPS Webhook
    ▼
Jenkins
desktop-control-plane
    │
    ├── Checkout
    ├── Docker Build
    ├── Docker Push
    │
    ▼
Docker Hub
ybtamiru/devops-php-todo
    │
    │ kubectl
    ▼
Kubernetes Cluster
    │
    ├── desktop-control-plane
    ├── desktop-worker
    └── desktop-worker2
         │
         ▼
    devops-todo namespace
         │
         └── todo-app
```

# 2. Important: GitHub Must Reach Jenkins

Your Jenkins server is running inside Docker on:

```text
desktop-control-plane
192.168.1.10
```

and Jenkins is exposed on:

```text
192.168.1.10:8081
```

This works from your local network:

```text
http://192.168.1.10:8081
```

However, GitHub's servers are **outside your local network**.

Therefore, GitHub cannot send a webhook to:

```text
http://192.168.1.10:8081/github-webhook/
```

because `192.168.1.10` is a private LAN address.

For this project, you need to expose Jenkins through a publicly reachable HTTPS URL.

There are two common approaches.

---

# 3. Option A — Public Server

If Jenkins is hosted on a cloud server with a public IP address, the webhook can use:

```text
http://PUBLIC_IP:8081/github-webhook/
```

For example:

```text
http://198.51.100.20:8081/github-webhook/
```

> The IP above is only an example. Do not use it.

For a professional deployment, HTTPS should be used instead of exposing Jenkins directly over HTTP.

For example:

```text
https://jenkins.yourdomain.com/github-webhook/
```

---

# 4. Option B — Local Jenkins with a Public Tunnel

For this project, Jenkins is running locally on `desktop-control-plane`.

Therefore, a tunnel can expose:

```text
http://localhost:8081
```

to the public internet.

One possible approach is **ngrok**.

On the machine running Jenkins:

```powershell
ngrok http 8081
```

You will receive a public HTTPS forwarding address similar to:

```text
https://abcd-1234.ngrok-free.app
```

Your actual GitHub webhook URL would then be:

```text
https://abcd-1234.ngrok-free.app/github-webhook/
```

Use the URL generated by your tunnel provider.

> ⚠️ Do not copy the example URL above. Your tunnel URL will be different.

---

# 5. Verify Jenkins Before Configuring GitHub

Before creating the webhook, make sure Jenkins is reachable from the public URL.

Open the generated HTTPS URL in a browser.

For example:

```text
https://YOUR-TUNNEL-URL.ngrok-free.app
```

You should see your Jenkins login/dashboard.

Your local Jenkins remains available at:

```text
http://192.168.1.10:8081
```

The public URL simply forwards requests to it.

# 20. Troubleshooting

## Jenkins does not start after `git push`

Check:

```text
GitHub
→ Settings
→ Webhooks
→ Recent Deliveries
```

If the webhook delivery failed, the problem is probably network connectivity between GitHub and Jenkins.

---

## GitHub cannot connect to Jenkins

If your Jenkins URL is:

```text
http://192.168.1.10:8081
```

GitHub cannot reach it because `192.168.1.10` is a private LAN address.

Use a publicly reachable HTTPS endpoint.

---

## Jenkins receives the webhook but does not build

Check that the Jenkins job has:

```text
☑ GitHub hook trigger for GITScm polling
```

enabled.

Also verify that the Jenkins job points to:

```text
https://github.com/Tamiru-Assefa/devops-php-todo
```

and the correct branch:

```text
main
```

---

## Jenkins build starts but Docker fails

Check the Jenkins container:

**Run on:** `desktop-control-plane`

```bash
docker ps
```

Find the Jenkins container and inspect its logs:

```bash
docker logs jenkins
```

Also verify that Jenkins can access Docker:

```bash
docker exec -it jenkins docker version
```

---

## Jenkins build succeeds but Kubernetes deployment fails

**Run on:** `desktop-control-plane`

Check:

```bash
kubectl get nodes
```

Then:

```bash
kubectl get deployment todo-app -n devops-todo
```

Check Jenkins' Kubernetes access and kubeconfig/RBAC configuration.

Also verify:

```bash
kubectl get pods -n devops-todo
```
